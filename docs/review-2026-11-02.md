# 프로젝트 리뷰 — 2026-11-02

검토 범위는 독립 실행형 Twitch Cup의 세 진입점, 참가·대진·iframe 계약, OAuth/채팅 연결, 화면 수명주기, 개발·테스트 설정이다. 원본 게임에서 남은 전체 시뮬레이션과 모든 미디어를 전수 검증한 리뷰는 아니다. Sol은 Twitch 흐름 검토·수정·회귀 테스트, Luna는 구조 조사와 문서 초안을 맡았고, 통합 검수와 실행 확인을 별도로 진행했다.

## 개발 작업 개선

- `npm run check`: 타입 검사 → 전체 테스트 → 빌드.
- `npm run preview`: 마지막 프로덕션 빌드를 5178 포트에서 확인.
- GitHub Actions 설정: Node 22, `npm ci`, `npm run check`, 읽기 전용 저장소 권한. 원격 실행은 아직 하지 않았다.
- `AGENTS.md`: 작은 진입 안내와 변경 범위별 코드 위치. `architecture.md`: 경계와 불변 조건. `testing.md`: 기능별 검증·수동 점검·한계.

## 1차 실행 결과

- 환경: Windows, Node v22.22.2, npm 10.9.7.
- 변경 전: 8개 테스트 파일, 44개 테스트와 타입 검사·빌드 통과.
- 변경 후: `npm run check` 통과. 9개 파일, 54개 테스트. 새 UI 테스트는 외부 인증·채팅·선수 API를 mock하고 실제 토너먼트 규칙과 iframe 메시지 검증을 사용한다.
- 의존성 설치 시 npm audit 결과 취약점 0개. jsdom은 테스트 전용 개발 의존성이다.
- Chrome 개발 서버에서 내장 선수 4명으로 준결승 2회·결승을 자동 완주하고 우승 표시를 확인했다. New cup에서 iframe 제거, 0/4, OPEN LOBBY 복귀도 확인했다.
- `npm run preview`로 빌드된 로비를 Chrome에서 확인했다. 세 HTML과 글꼴 세 파일의 HTTP 200 응답, 문서의 상대 링크, `git diff --check`를 확인했다.
- 실제 Twitch 로그인·채팅, 등록 선수 API, 실제 브라우저의 BFCache 복원은 미검증이다. 합성 페이지 이벤트 회귀 테스트와 구분한다.

## 남은 개선 후보

1. **첫 경기의 기기·네트워크별 시간 측정.** 후속 최적화로 가장 큰 두 청크 합계가 2,501,152 → 2,173,799 bytes로 줄었고 모듈 로드와 게임 부팅을 병렬화했다. 원인·측정 방법·검증은 [performance.md](performance.md). 실제 전송·파싱·전투 준비 시간 측정은 남아 있다. 경고 임계값은 유지한다.
2. **실제 브라우저 전투 자동화.** 현재 CI는 DOM 제어와 계약을 검증한다. Phaser 렌더링·오디오·세 경기 완주·실제 페이지 복원을 확인하는 브라우저 테스트는 별도 도입 대상이다.
3. **원본 게임 코드의 의존성 정리.** `src/app`, `src/sim`, `src/world`에는 추출 이전 기능도 남아 있다. 파일명만으로 삭제하지 말고 런타임/타입 import 및 미디어 참조를 확인하면서 작은 단위로 줄인다.

정적 파일·파일 감시 설정 근거와 개발 명령은 [testing.md](testing.md)에 연결된 공식 문서와 현재 설정 파일을 따른다.

## 2차 적대적 리뷰

정상 실행보다 응답 누락, 한 프레임에 여러 IRC 메시지가 섞이는 경우, 경기 사이에 호스트가 실패하는 경우를 검토했다. 이전 수정은 유지하고, 실패를 재현하는 좁은 테스트부터 추가했다. Sol에는 이전 UI 수명주기와 전투 호스트 검토를 맡겼다.

| 우선순위 | 재현한 문제 | 개선 |
| --- | --- | --- |
| P2 | 소켓이 열리지 않거나, 열린 뒤 채널 입장 확인이 오지 않으면 connecting/joining에서 무기한 대기 | 소켓 생성부터 입장 확인까지 15초 제한. 실패한 소켓을 폐기하고 기존 재시도 상한 적용. 정상 입장·연결 해제 시 타이머 제거 |
| P2 | 하나의 프레임에 `RECONNECT` 뒤 `ROOMSTATE`·참가 메시지·미완성 데이터가 붙으면, 폐기한 소켓이 다시 connected로 표시되고 새 연결의 입력까지 오염 | 매 줄 처리 후 현재 소켓인지 확인해 이전 프레임의 나머지를 버림. 재연결 대기 중 중복 connect 호출도 무시 |
| P2 | 경기 종료 후 다음 경기 전의 전역 오류가 게임 루프를 멈추지만, 완료된 경기라 실패 통지가 무시됨. 다음 경기가 멈춘 호스트를 사용하며 부팅 제한 시간을 반복 소진 | 호스트의 치명적 실패를 기억하고 다음 요청에 해당 요청 ID로 즉시 오류 응답. 수동 재시도는 기존대로 새 iframe을 생성 |

채팅의 연결 대기 두 경우·재연결 프레임, 호스트의 치명적 오류 세 경우는 수정 전 실패를 확인했다. 수정 후 `npm run check` 통과: 10개 파일, 64개 테스트와 타입 검사·빌드. 회귀 테스트는 총 10개 늘었으며 정상 연속 경기와 일반 로딩/경기 오류의 복구도 확인한다.

검증은 네트워크·호스트 경계를 통제한 회귀 테스트를 사용하며 실제 Twitch 장애나 Phaser 전체 런타임을 재현했다고 해석하지 않는다. 이번에는 의존성 추가나 광범위한 코드 정리를 하지 않았다. 기존 큰 청크 경고는 남는다.
